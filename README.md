# Cognitive Architecture v5

**机制派人格模拟器** —— 用一套固定机制让一个人格**长出来**，而不是扮演出来。

> 大多数「AI 人格」是靠提示词堆出来的：你告诉它"你是一个冷静、理性、说话简短的人"，
> 它就努力演出这个样子。**演得再好，底下还是空的。**
>
> 这个项目换了个路子：**不规定它该像谁，只给它一套机制**。
> 它的每一步思考都在算，算出什么就是什么。

---

## 这是什么

一个 Agent Skill：以**荣格八维**为出发点，但**做了大量改造** ——
术语全部重新定义，机制自己搭。

核心主张：

| 常规做法        | 本项目                  |
| ----------- | -------------------- |
| 人格 = 一段角色描述 | 人格 = **8 个功能强度值**    |
| 行为 = 按描述演   | 行为 = **公式算出来的结果**    |
| 记忆 = 塞进上下文  | 记忆 = **两层存储 + 遗忘曲线** |
| 稳定性靠提示词约束   | 稳定性靠**结构**，不靠自觉      |
| 遇到没依据的问题编一个    | 主动外求搜集资料或者询问用户                  |

**同一套机制 + 不同参数 = 不同的人。** 而且这个人会随经历积累而**变化** —— 记得越多，越像他。

---

## 与「扮演式」的本质区别

|        | 扮演式          | 本方案                      |
| ------ | ------------ | ------------------------ |
| 人格来源   | 提示词描述        | **8 个参数**                |
| 说话风格   | 直接规定（"说话简短"） | **由参数派生**，没人规定它该短        |
| 取什么材料  | 靠模型自己觉得      | **算出来**：比相似度 → 落区间 → 收或跳 |
| 记忆     | 全塞上下文，无限增长   | **两层存储 + 幂律遗忘**          |
| 会不会"忘" | 不会           | **会，且按曲线**               |
| 会不会"变" | 一般不会         | **会** —— 记忆积累影响后续行为      |
| 遇到没依据  | 编一个          | 出去找；找不到就**标「依据不足」**      |
| 随机性    | 是缺陷          | **是人格的组成部分**（不刻意压平）      |

## 核心设计

### 一、六个词素 —— 先立定义，再用

> ⚠️ **这是本项目的定义，不是荣格原义。** 术语同名但含义不同，一律以本表为准。

| 符号    | 中文       | 定义             |
| ----- | -------- | -------------- |
| **S** | **外源感知** | 内容**最初来自外部环境** |
| **N** | **内源感知** | 内容**是自己产出的**   |
| **T** | **逻辑判断** | 判断走**逻辑**路径    |
| **F** | **情感判断** | 判断走**情感**路径    |
| **i** | **聚焦模式** | 要求材料**彼此很像**   |
| **e** | **发散模式** | 要求材料**彼此不像**   |

**八功能名 = 模式 + 对象**：

```
Si = 聚焦式外源感知      Se = 发散式外源感知
Ni = 聚焦式内源感知      Ne = 发散式内源感知
Ti = 聚焦式逻辑判断      Te = 发散式逻辑判断
Fi = 聚焦式情感判断      Fe = 发散式情感判断
```

### 二、三层结构：分类 ≠ 程度

| 层       | 维度    | 性质      | 回答什么        |
| ------- | ----- | ------- | ----------- |
| **内容层** | S / N | **分类**  | 这条内容是**什么** |
| **判断层** | T / F | **分类**  | 怎么**处理**它   |
| **品质层** | i / e | **连续量** | 处理得**多一致**  |

关键区分：**前两层是两张分类表，第三层不是分类、是程度。**

> **这就是 v5 最根本的一步**：早期版本把 i/e 当成和 S/N 平行的"方向轴"，
> 于是写出「i 从 L 层取、e 从 W 层取」这种**写死的映射** ——
> 参数在那儿完全失效（你设了也没用）。
> 现在 i/e 是**一个可以算出来的品质要求**，四类对象共用同一套逻辑。

### 三、参数：8 个数进，两条轴出

用户只设 **8 个功能强度**（`Se Si Ne Ni Te Ti Fe Fi`），其余全部派生：

```
              ┌──▶ 聚焦度（决定「取哪一条」）
              │      focus_S = Si / (Si + Se)
8 个功能强度 ──┤      focus_N = Ni / (Ni + Ne)
              │      focus_T = Ti / (Ti + Te)
              │      focus_F = Fi / (Fi + Fe)
              │
              └──▶ 配额（决定「取多少」）
                     quota_S = (Si + Se) / (Si + Se + Ni + Ne)
                     quota_T = (Ti + Te) / (Ti + Te + Fi + Fe)
```

**两条正交轴**：

| 轴                 | 决定              | 用在哪       |
| ----------------- | --------------- | --------- |
| **聚焦度** `focus_*` | **取哪一条**（收 / 跳） | 提取步骤的逐条判定 |
| **配额** `quota_*`  | **取多少**（分容量）    | 分配步骤      |

> ⚠️ **这两条轴历史上被混用过**（拿"方向比"当"门槛"用），是本项目一连串 bug 的根子。
> 现在写死在文档里：**任何时候都不许混。**

### 四、主循环 —— 五步

```
① 分配   ← 定主/副、分容量
      ↓
② 提取   ← 凑齐这一轮要用的材料
      │     内部检索 → 定 anchor → 逐条判（收 / 跳）
      │     候选耗尽 → 外求（翻先验 / 搜资料 / 问用户）
      ↓
③ 判断   ← 用 T 或 F 处理这批材料
      ↓
④ 产出   ← 算 weight_S / weight_T
      ↓
⑤ 落盘   ← 分两份（内容份 / 依据份）
```

### 五、一致性怎么算 —— 偏相关剔除检索词

**这是 v5 里最漂亮的一块。**

问题在于：材料是**按检索词找出来的**，所以它们**必然共享检索词** ——
这个共同点会拉高彼此相似度，把**真正的角度差异埋掉**。

```
query = "台风"
材料 = 「历年台风有大有小」「台风的名字」「台风带来的影响」「我记忆中的台风天」
原始相似度 ≈ 0.45  ← 几乎全部是"台风"两个字贡献的
但四个角度其实毫不相干
```

**解法**：把 `query` 当共同成分扣掉，用**偏相关**看剩下的角度像不像：

```
              sim(anchor, 候选) − sim(query, anchor) × sim(query, 候选)
r = ────────────────────────────────────────────────────────────────────
              √(1 − sim(query, anchor)²) × √(1 − sim(query, 候选)²)

sim_angle = max(0, r)          # 截断到 [0, 1]
```

**刻度是干净的**：`0` = 角度全不同 · `1` = 角度全同。

**而且它是「取时逐条判」**，不是"取完再筛" —— 取用和筛选合成一步，
计算量从 O(n²) 降到 **O(n)**。

### 六、记忆：两层 + 遗忘 + 沉淀

| 层     | 类比       | 容量           | 机制             |
| ----- | -------- | ------------ | -------------- |
| **W** | 寄存器 / 缓存 | ~1000 tokens | 覆盖式，**不参与遗忘**  |
| **L** | 硬盘       | 无硬上限         | 持久化 + **幂律遗忘** |

```
R(t) = a0 · t^(−beta / strength)

  越久没调用 → 保留率越低
  每次被调用 → strength += 0.1 → 衰减更慢（复习效应）
  删除条件：R < 0.2 且 use_count = 0
```

**沉淀有两条路**：

| 路径       | 触发                       | 结果                |
| -------- | ------------------------ | ----------------- |
| **主动沉淀** | 被用作判断依据 / 产物落盘           | 加工产物，`weight_S` 低 |
| **重复沉淀** | 在 W 层反复出现 ≥ `repeat_m` 次 | 未加工，`weight_S` 高  |

> ⭐ **「死记硬背记得住、但忘得快」不需要任何额外规则** ——
> `weight_S` 高的内容取用面窄 → 很少被调用 → `strength` 不涨 → 按曲线衰减更快。
> **它是机制的自然结果，不是写上去的一条规则。**

### 七、挂起机制 —— 「问用户」不等于出轮

材料不够时可以问用户。但**问用户不是在换话题**，而是**同一轮缺材料、找人补**。

若按出轮处理，`query` 和 `anchor` 会被清掉 —— **前面的提取全白做**。

所以：把未完成状态（`pending`）存进 W 层，用户回答后**回到断点继续**。

## 亮点

1. **不扮演** —— 没有"它觉得怎样更像 INTJ"这回事，只有"参数是多少 → 算出什么 → 照做"
2. **结构约束强于行为约束** —— 命名、公式、区间判定，都是**让人没法弄错**，不靠提醒
3. **记忆会忘、会变** —— 幂律衰减 + 沉淀积累，人格随经历漂移
4. **「忘得快」是自然结果** —— 没为它加一行代码，机制自己长出来的现象
5. **一致性可以算** —— 偏相关剔除共同检索词，把"角度差异"从"语义重合"里剥出来
6. **纯提示词、零依赖** —— 不需要 embedding、不需要 API Key、不需要联网也能跑
7. **挂起而不丢状态** —— 中途提问不会让前面白做
8. **两条正交轴不混用** —— 历史上混用导致的 bug，现在写死禁止

cp -r cognitive-arch_v5 ~/.workbuddy/skills/cognitive-arch

## 快速开始

开局它会问你设哪 8 个功能强度（或直接选人格预设）：

```
/cognitive-arch preset INTJ        # 套用预设人格
/cognitive-arch set Ni=35 Te=30    # 直接改功能强度
/cognitive-arch show               # 看当前参数 + 派生量 + L 层统计
/cognitive-arch reset              # 恢复默认
```

**不改也行** —— 直接聊天，用出厂默认。

## 理论基础

源自荣格八维，经**机制化改造**：

| 概念      | 本项目的用法                              |
| ------- | ----------------------------------- |
| 八维功能    | 拆成 **8 个可调强度值**，不再是"类型标签"           |
| 内倾 / 外倾 | 重新定义为**对材料一致性的要求高低**（高 = 聚焦，低 = 发散） |
| 感知 / 判断 | 内容标签 vs 判断方式，**两张正交的分类表**           |
| 阴影功能    | 兜底值 5（不为 0）—— 功能"弱"不等于"无"           |

**三个保留的假说**（未验证的设计直觉）：

1. **发展时序** —— 功能在成熟过程中按顺序发展
2. **互补性** —— 不完整的认知链产生发展动力
3. **竞争性** —— 同类不同向的功能竞争同一资源
